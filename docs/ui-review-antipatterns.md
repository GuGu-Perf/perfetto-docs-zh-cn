# Perfetto UI Review 反模式

这是一份 UI 反模式及推荐替代方案的规范目录，**源自真实的 code-review
反馈**——维护者在对其他贡献者提交的 `ui/src/` pull request 中反复给出的意见。

**目的：** 供 AI agent（或人类）在 *code-review 或编写代码时* 阅读，
以便我们预先避免跨贡献反复出现的错误和无效假设，而不是在每个 PR 中
反复讨论。

如何使用：

- 每个条目格式为 **❌ 反模式 → ✅ 修复**，附带一行 *原因* 以及一个或多个
  可供查阅完整上下文的历史 PR 编号（`#NNNN`）。
- 🔁 标记表示跨**多个** PR 反复出现的规则——应给予最大权重；
  这些是维护者最强烈、最反复表达的偏好。
- 本文补充（并深入于）[`AGENTS-ui.md`](AGENTS-ui.md) 中的
  "Code Review Pet Peeves" 部分。当两者重叠时，两者都是权威的。

> 元原则，几乎贯穿以下所有内容：**不要过度工程化，重用已有的东西，
> 状态只存一处，让失败可见。**有疑问时，选择更简单、更小、更无聊的变更。

## 1. Mithril 与渲染

- 🔁 **❌ 手动调用 `m.redraw()` / `raf.scheduleFullRedraw()` → ✅ 依赖自动
  重绘。**Mithril 在 (1) 它注册的 DOM 事件处理器和 (2) trace-processor
  查询完成后会自动安排重绘。手动重绘仅在真正带外异步
  （`setTimeout`、`fetch`、`yield`）时需要。提交代码中的*绝大多数*手动
  重绘都是不必要的——删除它们。如果你认为需要手动重绘，首先找出 UI *为何*
  不更新；这通常指向别处的真正 bug，而非缺少重绘。当确实需要时，在事件
  发生点调用 `m.redraw()`（它不依赖于 `app`），而非
  `app.raf.scheduleFullRedraw()`。
  *(#4769, #4464, #4357, #4226, #3999, #3693, #3124, #2615, #1097, #5595, #5436, #5284, #5243)*

- 🔁 **❌ 将 `attrs`、设置或查询结果缓存到私有成员字段中 → ✅ 每次新鲜
  读取。**Mithril 将 `attrs` 传递给 `oncreate`/`onupdate`/`view`；从那里
  使用它们。设置存储已具有缓存支持——每次访问都读值，确保用户更改时
  不会过时。展示组件必须容忍其数据源每帧都可能变化。
  *(#3857, #6031, #4737)*

- **❌ `requestAnimationFrame` / `setTimeout` 时机 hack，希望 DOM 在"下一帧"
  就绪 → ✅ 使用恰当的渲染后回调。**用 rAF 规避 `ResizeObserver` 循环警告
  是代码异味。如果需要在渲染后执行操作，暴露一个从 `oncreate` 和
  `onupdate` 两处调用的 `onReady` 回调。*(#4761, #4146)*

- **❌ 将 `m.Children`（vnode）传入长期存在/一次性的 API（例如 modal）→
  ✅ 传递一个返回 `m.Children` 的函数。**存储的 vnode 会在多个渲染周期
  间被复用，这在 Mithril 中是未定义行为。传递 `() => m.Children`，使其在
  每次渲染时重新调用。同样，不要将 vnode 存储在 immer 控制的数据模型中
  （immer 不支持 vnode；它会破坏 undo/redo）。*(#4192, #3999)*

- **❌ 在生命周期钩子（`oncreate`、`onPopupMount`、构造函数）中做初始化/
  异步加载，而 `view()` 就能完成 → ✅ 在 `view()` 中计算，在正确的位置
  只初始化一次。**`onPopupMount` 仅用于真正需要 popup 的 DOM 元素的场合。
  构造函数在每次重新挂载时都会运行，因此其中的异步加载可能触发多次——
  在 plugin 的 `onTraceLoad()` 中加载一次，并通过 `attrs` 传入数据。
  *(#3817, #1389)*

- **❌ 用返回 `undefined` 的三元表达式处理条件子元素 → ✅ 短路写法
  `cond && m(...)`。**Mithril 会忽略 falsy 子元素。*(#2021, #1389)*

- **❌ 不必要的包装 `div` / 空的 `{}` attrs 或 `{style:{}}` 对象 → ✅ 将
  class 应用到已有元素上并省略空对象。** *(#5073, #4993, #2039, #1406)*

- **❌ `stopPropagation()` *和* `preventDefault()` 一起使用"以防万一" → ✅
  选择你真正需要的那个**，并说明它与其他处理器的交互方式。*(#3707)*

## 2. 状态、数据模型与生命周期

- 🔁 **❌ 为"方便访问"而使用模块级全局变量/静态字段/新建单例 → ✅ 注入
  依赖。**全局可变状态破坏了**多个 UI 实例可以在一个页面上运行**这一前提，
  并带来顺序/维护问题。通过 `trace`/`app` 对象传递状态（像 tabs 那样
  建模），或传递一个 context/settings 对象。Plugin 类本身实际上已经是
  单例——使用 `this.member`，而非 `static` 字段。
  *(#1097, #2036, #5436, #5284, #5286)*

- 🔁 **❌ 在单例 plugin 上缓存 `Trace` 对象 → ✅ 将 `Trace` 作为函数参数
  传递。**当第二个 trace 加载后，缓存的 trace 就成了*错误的* trace；进行中
  的异步函数随后会针对过期的 trace 完成解析。在 `onTraceLoad()` 中初始化
  每 trace 数据，并作为 `Readonly` 参数传递，这样还可以避免到处使用可选
  成员和 `!` 断言。要在不扩展 `Trace` API 的情况下附加每 trace 数据，可
  使用 `WeakMap<Trace, T>`。*(#5284, #2900)*

- 🔁 **❌ 为异步数据手写加载中/进行中布尔值和手动变更检测 → ✅ 使用
  `AsyncMemo`（以及 `AsyncLimiter`）。**直接由事件触发的 selection 驱动查询，
  在用户点击快于查询执行时会导致无限制的队头阻塞。使用 `AsyncMemo`
  （声明一个按值比较的 key，每次 render 调用 `.use()`，使用 `retainOn`
  渲染陈旧数据），或在 `TrackEventDetailsPanel.load()` 中加载，它会自动
  取消过期的加载。使用 `AsyncLimiter` 而非自定义标志来守卫并发。在
  `onremove()` 中销毁 `AsyncMemo` 实例是可选的（有助于提前取消进行中的
  任务或清理可释放的资源）。
  *(#4464, #4582, #4737, #5436, #4192)*

- **❌ 维护需要手动保持同步的派生状态 → ✅ 从单一数据源派生。**不要通过
  匹配选项来反向推导状态——持久化实际选择（例如 preset *名称*）并重新
  应用它。为异构项使用统一的 selection 列表，而非平行的 selection 状态。
  *(#3693, #3780, #3999)*

- 🔁 **❌ 将 UI 时间戳/持续时间存储为 JS `number` → ✅ 使用 `bigint`。**JS
  number 是 double，在 trace time 的大动态范围内会丢失精度。将 SQL 时间列
  类型化为 `LONG`/`LONG_NULL`，使其物化为 `bigint`（无需手动 `BigInt()` /
  无精度损失），并使用 `Time.fromRaw()` 而非强制转换。
  *(#2503, #4767, #4769)*

- **❌ 按人类可读的显示名称查询行 → ✅ 按稳定的有类型列查询**（例如
  `type = 'suspend_resume'`，而非 `name = "Suspend/Resume Latency"`）。
  显示字符串是脆弱的。*(#2149)*

- **❌ 忘记在 `onActivate()`、`onTraceLoad()` 或其他生命周期方法中 await
  异步函数调用。**调用异步方法而不 await 或 .then() 的正当理由极为罕见，
  因为这会创建 fire-and-forget 语义，导致竞态。如果确实需要，必须用注释
  记录。*(#2353, #1758)*

- **❌ 为可关闭提示/持久化布局使用临时 `localStorage` 键 → ✅ 使用设置
  系统**（并用 Zod 解析未知的持久化对象，使新增字段可选以保证向后兼容）。
  让 banner 可永久关闭；将一次性提示与永久可发现的按钮配对，而非重复的
  侵入式 banner。*(#5761, #2772, #3660, #3185)*

## 3. 架构与分层

- 🔁 **❌ `src/core` 或 `public/` API 接口中的厂商/产品/plugin 特定代码 →
  ✅ 将特定逻辑推入 plugin；保持核心接口通用。**这是错误的分层。同样
  适用于 chrome：不要向共享侧边栏添加 plugin 特定部分——通过 subtab/submenu
  将导航保留在 plugin 自己的页面内。将 plugin 特定常量（track kind）、
  工厂和 schema 保留在所属 plugin 内。
  *(#5284, #5153, #1624, #1241)*

- **❌ 将纯粹的通用库代码（track 实现、面板）包装为 plugin → ✅ 放入
  `ui/src/components`。**反过来，位于自己独立目录中的代码通常*应该*是一个
  `PerfettoPlugin`；如果不是，请重新考虑其位置。真正可复用的 widget 放入
  `widgets/`；*(#4767, #5284, #1097)*

- **❌ 隐藏的/偶然的跨 plugin 依赖（"碰巧"通过加载顺序生效）→ ✅ 显式
  声明依赖**，或将命令移到概念上所属的 plugin 中。在消费一个 track 之前，
  先依赖*创建*它的 plugin。不要仅为复用一个共享资源就引入重型 plugin
  依赖——将其提取出来（例如 `dev.perfetto.StandardGroups`）。
  *(#4613, #2666, #2137)*

- **❌ 继承/抽象基类层次结构，以及单方法的"manager"类 → ✅ 优先使用组合
  和独立函数。**只有一个方法且无状态的类应该只是一个函数。删除仅重新
  导出基础辅助函数的薄包装。*(#4844, #4184)*

## 4. Plugin 与 API 设计

- 🔁 **❌ Plugin 缺少/仅有占位符 `description` → ✅ 添加真实的
  `static readonly description`。**它会显示在 plugins 页面上，告诉用户该
  plugin 做什么以及为何启用它。不要写 TODO。
  *(#4716, #2394, #5436, #5284)*

- **❌ 在 plugin 中手动解析 `location.hash` → ✅ 使用 route-args 机制**——
  带 plugin 前缀的 URL 参数会被解码并作为 `onActivate()` 的第二个参数传入。
  使用标准约定（重复键或逗号分隔）和标准百分号编码设计 URL/查询参数格式；
  一旦外部用户采用了定制格式，它就成了你无法更改的接口。*(#5019, #2471)*

- **❌ 伸手进入内部结构（例如直接向 pinned-tracks 节点添加 track）→ ✅
  使用高层 API**（`TrackNode.pin()`）。先将 track 添加到正常 workspace 再
  pin，这样取消 pin 后它们仍留在树中。按 tag（例如 `trackIds` tag）过滤
  track，不要手工构造/猜测 track URI。*(#4814, #4820, #4524)*

- **❌ 将内部核心 schema 复用为传输/持久化格式 → ✅ 在本地定义外部
  schema。**复用意味着对核心类型的无关变更会静默改变本应稳定的契约。
  *(#4192)*

- **❌ 未使用的抽象接口/推测性的回调 props → ✅ 删除它们（YAGNI）。**
  不要引入无人实现的间接层，也不要为不支持的格式暴露选项然后再抛出异常。
  *(#4767, #5065, #1565)*

- **❌ 重启后才生效且无任何提示的设置 → ✅ 设置 `requiresReload: true`**
  以便提示用户重新加载。*(#2394, #1298)*

- **❌ `has()/get()` 后再修改、迭代查找第一个、总是成对使用的分离访问器 →
  ✅ 使用提供的辅助函数。**`getOrCreate(map, k, () => [])`、
  `result.maybeFirstRow({...})`（0 行时为 undefined），并将成对的访问器
  合并为一个函数。*(#5284, #4039, #2036)*

- **❌ 假设 stdlib 表可用 → ✅ 添加查询所依赖的 `INCLUDE PERFETTO MODULE`** (例如 `slices.with_context`)。*(#5392)*

## 5. Widget 与复用

> 🔁 **在构建任何东西之前先搜索 widget 库（`ui/src/widgets/`）。**"如果你
> 使用现有的 widget 和主题变量，这个文件的大部分内容都可以消失。"这是
> 最常见的一条复用意见。

- **使用现有 widget 而非原始 HTML 或手写标记：**`Button`/`RadioGroup`
  （而非 `<button>` 或 CSS 样式按钮——设置 `variant`/`intent` 来强调）、
  `Select`（而非 `<select>`）、`Anchor`（而非 `<a>`；外部链接使用
  `Icons.ExternalLink`）、详情面板用 `DetailsShell`、`Tabs`（而非
  `TabStrip` 或自制 tab——它会保留每个 tab 的组件，切换时不会重新加载
  数据）、`DataGrid`（已废弃的 `PivotTable` 正在被移除）、
  `DownloadToFileButton`（用于下载反馈）。
  *(#5153, #2394, #2772, #4582, #4464, #5276, #4226, #4481)*

- **❌ 重新实现 widget 已提供的行为 → ✅ 使用它的 prop。**用 `fillHeight`
  （在 `Editor`、`NodeGraph`、…… 上）代替 `height: 100%` CSS；用
  `closeOnOutsideClick`/`closeOnEscape` 或显式打开状态代替相互关闭的
  popup；将 overlay 挂载到滚动容器中的 `OverlayContainer`，而非手写
  锚点/可见性逻辑。*(#4993, #4027, #3124, #3711)*

- **❌ 覆盖 widget 的内部 class / 从外部重新实现其间距 → ✅ 将内容包裹
  在你控制的容器中，或使用 `Stack`。**对 widget 内部样式化很脆弱，
  widget 变更时会失效；应在 widget 自己的 SCSS 中修复尺寸问题。不要为
  属于共享 widget 的 bug 添加按消费者的 CSS 变通方案。
  *(#4027, #2615, #2394)*

- **❌ 仅为设置静态配置而继承 track/widget 类 → ✅ 以选项实例化它**
  （`new CounterTrack({trace, uri, sqlSource})`）。*(#5284)*

- **为仅图标的控件提供 `title`/tooltip 文本**，使其用途可被发现；轻量
  帮助优先使用 tooltip 而非 popup。*(#3185, #3124)*

- **添加新 widget 或 widget 选项时，在 widgets 页面添加 demo**，并针对
  边界情况（例如嵌套树节点）进行测试。*(#2383, #5659)*

## 6. CSS 与样式

- 🔁 **❌ 内联 `style={...}` → ✅ 将样式放入组件的 `.scss` 文件。**静态
  不变的样式永远属于样式表。*(#4737, #3185, #2394, #2615)*

- 🔁 **❌ 无前缀/通用的 class 名（`.row`、`.selected`、`.ai`）→ ✅ `pf-`
  前缀 + BEM。**通用选择器会与共享 widget 冲突（这是集成测试失败的一个
  真实原因），并在 Perfetto 被嵌入时失效。使用 `.pf-component`、
  `.pf-component__element`、`.pf-component--modifier`，将规则限定在其
  所有者之下（`.pf-node .pf-show-on-hover`），并使用 SCSS 嵌套
  （`&--horizontal`）。*(#2615, #1097, #2394, #3687, #3955, #1406, #2093, #5761, #2039)*

- 🔁 **❌ 硬编码颜色/魔法像素值/自造 CSS 变量 → ✅ 使用
  `theme_provider.scss` 中的主题变量/共享 token。**不要仅因为看起来合适
  就从无关领域借用变量（将 track 颜色用于非 track UI）——语义很重要。
  仅在绝对必要时指定背景颜色，以保持 UI 可主题化。
  *(#2615, #5153, #4991, #4185, #1097)*

- **❌ 通过字符串拼接/模板字面量构建 `classNames` → ✅ 使用 `classNames()`
  工具函数。** *(#3693, #2615, #1406)*

- **❌ 冗余声明（font-family/size、`cursor`、对 `pre`/`code`/`button` 的
  全局元素重置）→ ✅ 让它们继承 / 删除重复。**不要对页面元素设置
  `font-family`——让它从根继承以便主题生效。
  *(#5222, #3121, #2826, #2394)*

- **❌ 一次性 CSS 变量 / 将功能样式堆积到共享全局 SCSS 文件中 → ✅ 内联
  值；以聚合 import 启动一个专属根 SCSS。** *(#1097, #5243)*

- **杂项布局技巧：** `align-items: baseline` 对齐 widget 文本基线；
  `align-self: center` 对齐偏移的图标（不要更改容器）；`box-shadow` 用于
  focus 轮廓（避免加粗边框引起的布局偏移）；将 `<input>` 嵌套在其
  `<label>` 内以获得原生无障碍/点击行为；固定高度可滚动菜单以避免异步
  加载时的闪烁；避免使用 `<strong>` 和 translate/transform 悬停技巧来
  强调。*(#5222, #3121, #3946, #3844, #3817, #2615, #2093)*

## 7. TypeScript 与类型

- 🔁 **❌ `null` → ✅ `undefined`。**代码库在此处严格一致；使用 `?:` 可选
  语法。*唯一*允许的 `null` 是查询结果中的 SQL `NULL`——即便如此，在 UI
  代码中也优先映射为 `undefined`。*(#4192, #3599, #3188, #1389)*

- 🔁 **❌ 类型断言（`as`）和非空断言 `!` → ✅ 让 TS 窄化类型，或大声断言
  不变量。**TS 在 `.filter`、`Object.entries` 等之后会窄化；不要断言
  本身是 `unknown` 的类型。将对无类型数据的大量断言替换为 Zod 解析。
  使用 `assertExists(x)` 而非 `x!`，使开发者错误的 null 立即失败。使用
  `LONG`/`LONG_NULL` + `Time.fromRaw()` 而非强制转换 SQL 值。在可用时
  传递具体实现类型（`TraceImpl`）以避免下游强制转换。不要将查找包装在
  `Object(...)` 中——它会将类型抹除为 `any`；改为给查找表添加类型。
  *(#4767, #4890, #4769, #4653, #4613, #3331, #2580)*

- 🔁 **❌ 扁平接口带许多始终可选的字段，其有效组合未被强制执行 → ✅ 基于
  `kind`/`status`/`type` 标签的可辨识联合类型**（与共享字段交叉）。让
  类型系统强制每个变体需要哪些字段。*(#4192, #3331)*

- 🔁 **❌ 可变数组参数 → ✅ `readonly T[]`**（包括 getter/setter 中）用于
  不修改的集合。将接口 attrs 标记为 `readonly`。
  *(#3188, #3058, #2039)*

- **❌ 穷举 `switch` 的 default 中缺少 `assertUnreachable()` → ✅ 添加它**，
  使编译器在添加新的联合类型 case 时报错。*(#2615, #1565)*

- **❌ 用新的包装接口重复已有类型，或将数据路由通过宽泛/通用接口再重新
  解析 → ✅ 直接返回已有/正确的特定类型**（例如返回 `QueryResult`；
  返回 `AndroidInputEventSource` 而非解析回来的通用 args）。在接受普通
  `number` 的 API 上去掉品牌类型（`SliceSqlId`）。
  *(#4844, #4767, #4729)*

- **❌ `== null` 比较 / 通用 `==` / 过早合并到 sentinel 值 → ✅
  `if (!x)`、`x ?? 0`、nullish 运算符。**注意 JS falsy 陷阱：`0` 和
  `null`/`undefined` 都是 falsy——通过 `(number|null)[]` 携带 `null`，
  将真实的 `0` 显式显示，而非将其渲染为空白。
  *(#1582, #1389, #1376)*

- **较小类型规范：**没有 `await` 的函数不要标记 `async`；添加
  `declare global { interface Window {...} }` 扩充以注入到 `window`
  （不要强制转换）；在类型繁重的代码中为中间变量添加显式注解；不要强制
  接口属性为 getter（使用普通 `readonly`）；不要冗余初始化构造函数始终
  赋值的字段；当其他分支返回值时，优先使用显式 `return undefined` 而非
  裸 `return`；避免将数字键通过字符串来回转换；不要无意中扩大成员的
  可见性（`private`→`public`）；不要添加始终被提供的可选参数。Zod schema
  必须镜像实际的嵌套数据形状。
  *(#4278, #4192, #2644, #2615, #1763, #2897, #5222, #3058)*

## 8. 命名与约定

- 🔁 **ID 遵循既定约定。**设置/注册 ID：反向 DNS，核心属 `dev.perfetto.*`，
  外部 plugin 使用贡献者组织的命名空间（`com.meta.*`、`com.android.*`）。
  命令 ID：省略冗余的 plugin 名称，使用稳定的命名空间化动词形式，以便
  命令可在 plugin 之间移动。**不要将设置的 ID 与 plugin 名称绑定**——
  与 plugin 无关的 ID 使其可在不丢失用户保存值的情况下重定位。不要对仅在
  你自己的 plugin 内注册的内容过度命名空间化。
  *(#5787, #5761, #3362, #3259, #2036, #4653, #4767, #5436)*

- 🔁 **变量/成员使用 camelCase；文件名使用 `snake_case`；不使用匈牙利
  命名法。**不使用 `snake_case` 变量（`trace_processor_id`），不使用
  缩写前缀（`uMachineIds` → `uniqueMachineIds`），私有方法不使用前导
  下划线，仅在参数有意未使用时*才*添加下划线前缀。
  *(#2615, #1155, #1913, #1389, #1565, #4737)*

- **以事物本身/所做的事情命名，在合适的抽象层级。**只显示（从不切换）的
  函数命名为 `showX`，而非 `toggleX`。一次性 init 函数命名为
  `load`/`initialize`，而非 `build`（读起来像每帧 Mithril 辅助函数）。
  Widget 使用标准术语命名（`treemap`、`scatterplot`），而非
  `treemap_chart`。当 widget 范围扩大时重命名它。当上下文中所有内容都
  已有限定词时，删除冗余限定词。不在一个标识符中使用两个同义词
  （`canvas`/`container`）。布尔值以其守卫的内容命名
  （`isProcessingQueue`，而非 `isProcessing`）。如果预期复用，按通用
  概念命名字段。使命令名称自解释/可发现。
  *(#3169, #4192, #4761, #4729, #4278, #1406, #1302, #4380, #5566)*

- **机械约定：**每个新文件包含版权头（新文件使用当前年份；编辑时不要
  改动年份）；仓库内模块使用相对 import 标识符；使用 `//` 行注释在行上方
  或右侧，不使用 `/* */`；运行 `ui/format-sources`（不要手动格式化）；
  检查新默认快捷键是否与现有全局快捷键冲突。
  *(#2394, #4582, #4769)*

## 9. 错误处理

- 🔁 **❌ 吞掉错误（空 `catch`、`console.warn`、返回 `undefined`）→ ✅
  让失败可见。**控制台消息在实践中会被忽略。对于**开发者错误，让它崩溃**
  （保留 stacktrace + 分析）；对于**预期失败，向用户显示消息**（例如
  `showModal`）。空 catch 会在重构期间静默吞噬拼写错误。
  *(#4582, #4344, #4192)*

- **❌ 在异常引发处捕获 → ✅ 冒泡到合适的粒度。**让调用方的循环捕获并跳过
  失败项，而非在辅助函数内部逐项吞噬。考虑返回 `Result<T>`（StatusOr 风格）
  以强制调用方显式处理失败。*(#4192)*

- **❌ 宽泛的 `try` 块 → ✅ 仅包裹实际可能抛出的调用**，而非周围的设置
  代码。*(#4192)*

- 🔁 **❌ 非空 `!` / 静默回退到全局默认值 → ✅ 对开发者错误不变量使用
  `assertExists()`。**例如 `assertExists(canvasElement)`——绝不意外回退到
  `document`；对不可能状态使用 `assertExists(queue.shift())` 而非防御性
  的 `if (!blob) continue`。*(#4994, #4761, #2580, #1302)*

- **❌ 无超时的网络 fetches / 阻塞核心流程 → ✅ 使用 `fetchWithTimeout`
  并显示软错误。**不要依赖浏览器的约 5 分钟默认超时；核心
  路径上的细粒度延迟 fetches 有"UI 在流程中悄悄停止工作"的风险。（也不
  要*过于激进*地设置超时——10 秒以上，人们会使用热点网络。）
  *(#4192)*

- **❌ `try/catch` 没有明确处理的目标，或对预期的空条件发出警告 → ✅
  保持明确。**不要对首次运行的 `localStorage` 状态缺失发出警告。在确认
  失败路径已被处理之前，不要*移除*可能失败查询周围的已有 try/catch 守卫
  （这可能导致非 Google 环境出错）。*(#2615, #4115, #1513)*

- **❌ 一行有问题就中止整个批次 → ✅ 跳过/丢弃该行并继续。**确保处理器在
  处理中途抛出异常时不会使共享状态不一致。*(#2897, #1302)*

## 10. 性能

- **虚拟化：**对不需要可变行高且高度受限的 grid 启用虚拟化；保留 grid

  *(#5222, #5436, #1389, #1097)*

  *(#5284)*
